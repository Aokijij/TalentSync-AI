# Almacenamiento privado de producción en Cloudflare R2

TalentSync admite R2 para CV originales, fotos de perfil y logos/portadas de
empresas. Las versiones de CV guardadas permanecen en PostgreSQL. El bucket se
mantiene privado: las descargas pasan por las rutas autorizadas del backend y no
se generan enlaces públicos permanentes.

## Configuración

Crear un bucket de clase **Standard** y mantener desactivados el dominio público
de desarrollo y los dominios públicos personalizados. Crear un token de cuenta
R2 con **Object Read & Write** limitado exclusivamente a ese bucket. Guardar
Access Key ID y Secret Access Key; no se usa el campo Token value de la API REST.

Inyectar estas variables únicamente en el backend, junto a su configuración
completa de producción y la conexión PostgreSQL:

| Variable | Contenido |
| --- | --- |
| `R2_ENDPOINT_URL` | Endpoint S3 HTTPS de la cuenta, sin el nombre del bucket ni parámetros. |
| `R2_BUCKET` | Nombre exacto del bucket privado. |
| `R2_REGION` | `auto`. |
| `R2_ACCESS_KEY_ID` | Access Key ID de la credencial S3. |
| `R2_SECRET_ACCESS_KEY` | Secret Access Key de esa credencial. |

Los buckets jurisdiccionales usan el endpoint específico de su jurisdicción.
El backend rechaza configuraciones parciales, endpoints ajenos a R2 o sin TLS,
y la activación simultánea de Azure y R2. Si R2 falla, no se consulta un disco
local como alternativa. Las credenciales R2 se ocultan en representaciones de
configuración y los errores públicos no incluyen mensajes del proveedor.

En este equipo, `.local/r2-production.env` es el archivo privado de preparación,
excluido de Git y de la imagen Docker. `scripts/local.py` mantiene R2 desactivado
para que pruebas y sesiones locales no usen accidentalmente el bucket real.
No configurar estas variables como `VITE_*` ni añadirlas a archivos versionados.

## Operación y comprobación

- Los CV originales usan `users/{id}/cv.pdf`; las fotos mantienen el prefijo
  exacto `profile_photos/user_{id}_`. Los archivos de empresa están separados.
- Las fotos nuevas no pueden sobrescribir un objeto existente. Un CV nuevo
  sustituye el original de su propietario después de extraer el PDF correctamente.
- Los PDF se procesan mediante un archivo temporal que se elimina al terminar,
  tanto si la extracción tiene éxito como si falla.
- Las lecturas tienen límites de tamaño; las conexiones y reintentos son acotados.
- `/health/ready` comprueba el acceso al bucket mediante un listado limitado;
  `/health/live` no depende de R2.
- Exportar o eliminar una cuenta solo enumera sus dos prefijos exactos. La
  exportación verifica ETag y tamaño, admite como máximo 1.000 archivos y 50 MB,
  y conserva el aislamiento entre usuarios como `1` y `10`. Un fallo de borrado
  continúa mediante el mecanismo de reintento persistente de la plataforma.
- La prueba real de conexión usa únicamente un objeto sintético con clave UUID,
  comprueba escritura/lectura y después lo elimina. No importa archivos personales.

Cambiar de proveedor no migra archivos existentes automáticamente. Antes de
cambiar un despliegue con datos, copiar y verificar los objetos y preparar la
reversión. Para una instalación nueva no se importa el contenido local de prueba.

R2 incluye una cuota gratuita mensual, pero cobra los excesos. Mantener clase
Standard, revisar consumo y configurar avisos; los avisos no bloquean el gasto.
